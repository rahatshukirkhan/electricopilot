# 13 — Экспорт документации (SLD + журнал + спецификация + пакет)

Фаза 2 плана v3 (`docs/12 §2`). Из модели щита — кнопкой — получаем комплект: однолинейную
схему (SVG + DXF), кабельный журнал (XLSX), спецификацию (XLSX) и отчёт (MD), собранные в один
zip. Всё считает детерминированный код; LLM не участвует.

## 13.1 Архитектура пакета `src/electricopilot/export/`

Единый **источник геометрии** — `primitives.py`; рендереры «тупые» (переводят примитивы 1:1).

| Модуль | Роль |
|---|---|
| `primitives.py` | Плоские примитивы (`Line/Polyline/Rect/Circle/Text`, `Drawing`). Координаты — **мм, ось Y вниз**, origin верх-лево (layout читается «сверху вниз»). У `Line/Polyline` есть `color`-override (для «статус цветом»). |
| `symbols.py` | Условные обозначения (упрощённо по ГОСТ 2.755): автомат `breaker`, УЗО/АВДТ `rcd`, предохранитель `fuse`, шина `bus`, стрелка нагрузки `load_arrow`, рамка листа со штампом `sheet_frame`. Каждый — чистая функция `(x, y, …) -> list[Primitive]`; текстовые подписи добавляет `sld.py`. |
| `sld.py` | Layout однолинейки → **один `Drawing` на лист**. |
| `svg.py` | `Drawing -> str` (SVG). Детерминированный (без плавающих id, фикс. точность) — годен для golden-снапшота и для предпросмотра в Studio. |
| `dxf.py` | `Drawing -> bytes` через **ezdxf**. Ось Y переворачивается (CAD — Y вверх). |
| `tables.py` | Общий `Table` (заголовок/колонки/строки/примечания). |
| `cable_journal.py` | Кабельный журнал (форма по мотивам ГОСТ 21.613) → `Table`. |
| `boq.py` | Спецификация (группировка) → `Table`. |
| `xlsx.py` | `Table -> bytes` (XLSX) через **openpyxl**. |
| `bundle.py` | `build_bundle(project) -> bytes` — zip в памяти. |

Структурированные данные для экспорта приходят из `project.build_project_report`: каждая строка
`report["rows"]` несёт под-словарь `spec` (сечение/материал/изоляция/метод/жилы/In/класс/кривая/
УЗО), поэтому экспорт **не парсит отображаемые строки**. `report["norm_pack"]` несёт
`name`, `version`, происхождение `status` и вычисленный `verification_status`; полный
структурный аудит находится в `report["data_provenance"]`.

## 13.2 Однолинейная схема (layout-правила)

- Лист **A3 альбомный** (420×297 мм), рамка + внутренняя рамка + штамп-заглушка (низ-право).
- **Ввод слева** → вертикальный спуск в **горизонтальную шину** (слой `BUS`, синяя).
- Отходящие цепи — **вертикальные колонки**, равномерно по ширине. На колонке сверху вниз:
  обозначение (ref) под шиной; символ аппарата (**предохранитель для `gG_fuse`**, иначе
  автомат); символ УЗО (если `spec.rcd.present`); длинный
  **повёрнутый на 90° сводный ярлык** (аппарат/кривая/УЗО · кабель · L · IB/ΔU); описание и
  **статус** снизу. Провод цепи окрашен по статусу (`PASS` зелёный, `FAIL` красный,
  `NEEDS_REVIEW` жёлтый).
- **> 16 цепей на лист** → разбивка: `build_sld` возвращает несколько `Drawing`.
- Каждый лист несёт футер: дисклеймер, `UNSIGNED_ADVISORY`, имя/версию/происхождение
  норм-пакета и его `VERIFIED|NEEDS_REVIEW`. SVG и DXF строятся из одного `Drawing`, поэтому
  формулировка совпадает побайтно на уровне текста.

## 13.3 Кабельный журнал (XLSX)

Колонки: `Обозначение | Начало | Конец | Марка (заглушка) | Сечение | Длина по проекту, м |
Длина с запасом, м | Способ прокладки`. Запас — коэффициент `project.export_settings.cable_margin`
(по умолчанию **1.05**). **«Марка» — честная заглушка**: конкретная марка кабеля — каталожные
данные (Фаза 6), не выдумываются.

## 13.4 Спецификация / BoQ (XLSX)

Группировка одинаковых **аппаратов** (класс+In+кривая+УЗО → штуки) и **кабелей**
(жилы+сечение+материал+изоляция+метод → метры с запасом). Детерминированный порядок (сортировка
по наименованию), поэтому вывод стабилен и тестируем.

## 13.5 DXF / SVG

- **DXF-слои:** `FRAME`, `BUS`, `WIRES`, `SYMBOLS`, `TEXT` (ACI-цвета). Версия **R2010**, текст
  UTF-8 — кириллица сохраняется в бесплатных вьюерах (LibreCAD, ODA File Converter). Статус-цвет
  провода — `true_color` на entity.
- **SVG** — детерминированный, тот же `Drawing`; используется и в предпросмотре Studio.

## 13.6 API и UI

```
POST /api/project-report {project} ?sld=1 → отчёт (+ `sld:{svg,sheets}` при ?sld=1)
POST /api/project-sld     {project} → {svg, sheets}            (предпросмотр, 1-й лист)
POST /api/project-export  {project} → application/zip          (пакет; имя из board_ref, RFC 5987)
```
`?sld=1` у `/api/project-report` вкладывает предпросмотр однолинейки в тот же ответ (SLD — чистая
функция уже посчитанного отчёта), поэтому экран щита и печать делают **один** вызов = **один**
проход движка, а не два. Рендерится только 1-й лист (полный набор листов — в пакете).
Норм-пакет берётся из `project.norm_pack`; ошибка пакета → `400`. UI (экран щита): кнопка
**«📦 Пакет документов»**, панель **«Однолинейная схема»** с живым SVG-предпросмотром, кнопка
**«🖨 Печать»** → маршрут `#/p/<id>/print` (печатная страница: таблица щита + итоги + однолинейка
+ провенанс, `@media print`, `@page A4 landscape`). **PDF — браузерным «Сохранить как PDF»**;
серверный PDF не делаем (тяжёлые зависимости в serverless).

## 13.7 Пакет (zip)

`report.md`, `sld.svg`, `sld.dxf`, `cable_journal.xlsx`, `boq.xlsx`, `project.json`
(много листов → добавляются `sld-2.*`, `sld-3.* …`). Каждый документ несёт дисклеймер и
провенанс-ноту пакета данных, его имя/версию/статус проверки, дисклеймер и
`UNSIGNED_ADVISORY`. Даты zip-записей фиксированы; `report.md`, SVG и XLSX
байт-детерминированы (у XLSX openpyxl-таймстампы нормализуются `xlsx._normalize_xlsx`). Только
DXF недетерминирован (ezdxf вшивает свои GUID/таймстампы), поэтому архив целиком не
байт-идентичен между запусками.

## 13.8 Ограничения (осознанные)

- Условные обозначения и layout — **иллюстративно-схематичные** (упрощённо по ГОСТ 2.755), не
  замена нормоконтролируемого чертежа; штамп — заглушка.
- Марки кабелей и артикулы аппаратов — заглушки до Фазы 6 (каталог).
- Пределы ΔU и прочие числа — из выбранного норм-пакета (для `iec-stub` синтетические); экспорт
  наследует статус пакета и его провенанс.
- Печать/PDF — на стороне браузера; серверного рендера PDF нет.
