# ТЗ 18 — Пересмотр UX-потоков: кликабельный прототип

Статус: спека для ветки `feat/ux-flows-prototype` (от `feat/design-blueprint-light`). Это ПРОТОТИП для приёмки заказчиком на Vercel-preview, не продовая перестройка. Исполнитель следует буквально; неоднозначность — СТОП и вопрос.

## 0. Диагноз (зачем)

Экраны Studio повторяют модель данных (проект → цепь → расчёт), а не рабочий процесс электрика. Заказчик подтвердил четыре боли: (1) щит без иерархии действий и без запасов в таблице; (2) в редакторе нет крупного вердикта и живого пересчёта, копилот занимает премиальное место; (3) подпись выглядит как обычная кнопка; (4) тревожный фон — оранжевые простыни дисклеймеров, тосты по центру, красное «не сохранено».

## 1. Сценарная карта (целевой поток электрика)

1. **Задание** → создать щит: ввод (U, фазы, система заземления), число мест.
2. **Наполнение** → цепи вручную / описанием словами / импортом XLSX.
3. **Подбор** → по каждой цепи: параметры → мгновенный результат с запасами → при необходимости графики и обоснование по пунктам норм.
4. **Проверка** → нормоконтроль всего щита; замечания ведут прямо в проблемную цепь; чинишь — перепроверяешь.
5. **Документация** → пакет документов / печать / share.
6. **Подпись** → осознанный финальный акт: сначала цепи, затем щит; всегда видно, что именно подписываешь.

Прототип обязан сделать этот порядок очевидным из самих экранов.

## 2. Форма прототипа (технически)

- Три новых файла: `web/prototype.html`, `web/prototype.css`, `web/prototype.js`. Существующие `index.html`/`app.js`/`styles.css` НЕ трогать вообще. `src/**`, `api/**`, `tests/**` не трогать.
- `prototype.html` подключает `./styles.css` (токены Blueprint Light) + `prototype.css` поверх; шрифты и Plotly CDN — как в index.html.
- Данные — захардкоженный мок щита «ВРУ-1 (пример)» из 4 цепей (L1 розетки 2.5мм²/20A/2.26%, L2 освещение 1.5мм²/15A/1.7%, L3 бойлер 2.5мм²/20A/2.04%, M1 двигатель 10мм²/44.5A/1.08%, пределы ΔU 5%). Никаких запросов к API; «живой пересчёт» имитируется детерминированной клиентской функцией на моках (это прототип UX, числа иллюстративные — пометить в футере прототипа).
- Экраны — секции с клиентской навигацией (как screen'ы в app.js): Щит ↔ Цепь + модал подписи. Вся навигация кликабельна.
- Словарь отображения ТЗ 17 действует (русские метки + код в title). Язык — русский, терминология электрика.

## 3. Экран «Щит» (прототип)

1. **Шапка-карточка щита** (вместо россыпи кнопок): имя, DB-1, ввод «400 В · 3ф · TN-C-S», расчётный ток ввода ≈33 А, резерв мест 8/12, статус нормоконтроля (чип), прогресс подписи «Подписано 0 из 4».
2. **Панель «Следующий шаг»** (правая колонка, всегда видна): динамическая подсказка по состоянию — «Запусти нормоконтроль» → после прогона «2 замечания · открой L2» → «Все проверки пройдены → сформируй пакет документов» → «Подпиши цепи». Одна акцентная кнопка текущего шага. Ниже — группа «Документы»: Пакет документов, Печать, Share-ссылка, Файл проекта (ghost, вторичные).
3. **Таблица цепей с запасами** вместо голых чисел:
   - колонка IZ: «20 A» + подстрока/мини-бар запаса «+19 % к IB»;
   - колонка ΔU: «2,26 % из 5» + мини-бар заполнения лимита;
   - статус-чип показывается ТОЛЬКО если отличается от «Соответствует» (норма — тишина, отклонение — сигнал);
   - после «нормоконтроля» (кнопка в прототипе прогоняет мок) строки с замечаниями получают маркер, клик по замечанию ведёт в цепь.
4. **Нормоконтроль** — компактный блок под таблицей: список замечаний «R04 · L2 · ΔU близко к пределу — [Открыть цепь]», не панель-простыня.
5. Однолинейку на этом экране свернуть в details «Однолинейная схема» (по клику), чтобы не давила на поток.

## 4. Экран «Цепь» (прототип)

1. **Вердикт крупно** (первый элемент центра): «2,5 мм² Cu/PVC — проходит · запас по току +19 % · ΔU 2,26 % из 5 · определяет: координация по перегрузке». Цвет статусный; при мок-изменении параметров вердикт обновляется мгновенно.
2. **Живой пересчёт**: изменение любого поля левой формы (группы из ТЗ 17 сохранить) обновляет вердикт и мини-значения без кнопки; кнопку «Пересчитать» убрать. Для прототипа — мок-функция: длина влияет на ΔU линейно, сечение — ступенчато (данные захардкодить для 3–4 комбинаций, остальное — «в прототипе не считается», показывать честную заглушку).
3. **Графики** — вкладки как сейчас (русские названия из ТЗ 17), Plotly с мок-данными для L1; при переключении цепей достаточно L1 живой, остальные — заглушка «в прототипе доступна цепь L1».
4. **Копилот** — свёрнут: кнопка «Спросить копилота» в правом верхнем углу центра открывает выдвижную панель справа (в прототипе — статичная имитация диалога). По умолчанию панель закрыта, её место занимает «Обоснование расчёта · по пунктам норм».
5. **Подпись — отдельный поток**: кнопка «Подписать цепь» (не рядом с «Сохранить», визуально отделена) открывает модал: сводка подписываемого (параметры, результат, норм-пакет, оговорка о синтетических данных), чекбокс «Я, инженер, проверил расчёт и принимаю ответственность», акцентная кнопка «Подписать», после — бейдж «Подписано» и обновление прогресса на щите. Отмена — явная.

## 5. Спокойный фон (в прототипе)

- Дисклеймер — одна строка под шапкой: «Рекомендательный расчёт · нормы синтетические · подробнее» (details/попап с полным текстом). Оранжевую ленту-простыню не воспроизводить.
- Тосты — правый нижний угол, автоскрытие 4 с.
- Статус сохранения — спокойный: «сохранено» / «сохранено локально · без синхронизации» серым, без красного (красный только для реальной потери данных).
