# 11 — Studio v2: проектный инструмент (щит с множеством цепей)

Превращает Studio из просмотрщика одного расчёта в **рабочую среду проектировщика**: инженер
ведёт несколько **проектов-щитов**, в каждом — множество **цепей**, видит сводную **таблицу
щита (panel schedule)** с тоталами/балансом фаз, подписывает и экспортирует проектный отчёт.
Полная дизайн-спека (51 требование) — в наработках воркфлоу; здесь — реализуемый MUST-объём.

## 11.1 Информационная архитектура

Три сущности: **Workspace** (контейнер тестировщика) → **Project** (щит) → **Circuit** (цепь).
Три экрана (hash-роутинг, надёжно на статике):

| Маршрут | Экран |
|---|---|
| `#/` | **Дашборд проектов** — карточки щитов (имя/ref, число цепей, rollup PASS/REVIEW/FAIL, «изменён»), действия: создать/открыть/переименовать/дублировать/удалить(confirm+undo)/экспорт/импорт, «загрузить пример». |
| `#/p/:pid` | **Щит** — шапка щита, **panel schedule** (строка на цепь), футер тоталов (Σнагрузка, баланс фаз, резерв мест, rollup), быстрое добавление + NL-ввод, кнопки: отчёт/экспорт/импорт/уставки щита. |
| `#/p/:pid/c/:cid` | **Редактор цепи** — существующий воркбенч (форма + графики TCC/свип/ΔU/дерейтинг/однолинейка + копилот + трасса), хлебные крошки, назад-к-щиту, пред/след цепь, подпись цепи. |

## 11.2 Данные (localStorage; Neon — fast-follow)

Ключи: `ec_v2_workspace`, `ec_v2_projects` (индекс), `ec_v2_project_<id>` (полный проект,
атомарная запись). Legacy `ec_circuits` мигрируется один раз.

- **Project**: `{id,name,board_ref,location,created_at,updated_at,supply{voltage_v,phases,ways_total,earthing,incomer,ipf_ka,method,material,insulation,ambient},diversity{factors},circuits[]}`.
- **Circuit**: `{id, ref, sort_index, request(SizingRequest), meta{phase,rcd{present,ma,type},diversity_category,cores}, result{status,section,In,IB,Iz,vd,governing}, signoff{status,engineer,license,signed_at,ack_illustrative}}`.
- **meta** — только для щита/отчёта, движок их не использует (не меняем `models`/`engine`).

## 11.3 Panel schedule и тоталы

**Колонки строки:** ref · описание · кВт/кВА · cosφ · фаза · IB · аппарат(класс+In+кривая) ·
УЗО/IΔn · кабель(мм²+жилы+мат/изол+метод) · длина · IZ · ΔU% · КЗ/откл · статус.

**Тоталы щита:**
- Σ подключённой: `Σ кВт`, `Σ кВА` (кВА = кВт/cosφ).
- **Баланс фаз (реальный):** `IL1/IL2/IL3 = Σ IB` цепей на фазе (3ф цепь добавляет IB во все три);
  `imbalance% = (Imax−Imin)/Iavg`; флаг при > 20 %.
- **Расчётная нагрузка (иллюстративно, редактируемо):** `EMD = Σ(кВт·df_категории)`; df помечены
  `PROVENANCE_NOTE_ILLUSTRATIVE` (метод реальный, значения df — синтетические).
- **Резерв мест:** `spare = ways_total − used`.
- **Rollup щита:** худший из цепей (любой FAIL⇒FAIL; иначе любой NEEDS_REVIEW⇒REVIEW; иначе PASS).

**Реальное vs синтетическое:** IB/In/IZ/ΔU/адиабатика/статус — реальная методология + реальные
ссылки IEC, но **синтетические значения**; баланс фаз — реальная арифметика; df — синтетика.

## 11.4 Бэкенд (добавка)

`POST /api/project-report` — принимает проект, **пересчитывает каждую цепь реальным `size()`**
(не доверяет клиентским снимкам), возвращает `{board{status,rollup,totals,demand,ways}, rows[],
markdown, provenance_note, disclaimer}`. Существующие эндпоинты не меняются.

## 11.5 Экспорт / доверие

- **`.ecproj.json`** — раунд-трип проекта (импорт создаёт новый проект с новыми id) — бэкап/передача без логина.
- **Проектный отчёт** (Markdown/print): обложка(щит+уставки+дисклеймер), таблица щита+тоталы,
  подетальная трасса каждой цепи, блок подписи (per-circuit + проект).
- **Доверие в UI:** постоянная плашка «рекомендательно · синтетические значения · реальные ссылки
  IEC · нужна подпись инженера»; на графиках «иллюстративные значения»; вердикт — «иллюстративная
  проверка»; бейдж UNSIGNED_ADVISORY на карточке/строке/редакторе; подпись цепи с обязательным
  подтверждением (`ack_illustrative`).
- **Без потери данных:** атомарная запись, автосейв + индикатор, обновление-на-месте (не дубль),
  удаление confirm+undo, валидация ввода, неблокирующие ошибки/пустые состояния.

## 11.6 Границы этой итерации

MUST (выше) на localStorage, zero-config. Fast-follow: Neon-персистентность на workspace-token,
PDF/CSV, сквозной ΔU и каскад КЗ по под-щитам, per-project rollup подписи, наследование уставок щита.
