# 01 — Доменный анализ: методология подбора по IEC 60364

> Все ссылки на пункты/таблицы (clause/table id) — **реальные** идентификаторы стандартов.
> Числовые значения таблиц в норм-пакете прототипа — **иллюстративные** (см. `04`).
> Раздел описывает методологию (общедоступное инженерное знание), а не текст стандарта.

## 1.1 Расчётная цепочка

```
Нагрузка (P или I, U, cosφ, фазность)
        │
        ▼
 IB  расчётный ток цепи
        │
        ▼
 In  номинал аппарата защиты   ── дискретный ряд, In ≥ IB
        │
        ▼
 It  табличная пропускная способность кабеля (опорные условия)
        │  × поправки (темп. ka, группировка kg, …)
        ▼
 IZ = It · ∏k   длительно допустимый ток кабеля (скорректированный)
        │
        ▼
 Проверки:
   (A) координация перегрузки:  IB ≤ In ≤ IZ  и  I2 ≤ 1.45·IZ
   (B) падение напряжения:      ΔU% ≤ предел
   (C) термическая стойкость КЗ: S ≥ I√t / k   (адиабатика)
        │
        ▼
 Итоговое сечение S = наименьшее стандартное, проходящее ВСЕ проверки
 Governing constraint = какая проверка оказалась связывающей
```

## 1.2 Расчётный ток IB

Если задан ток — `IB = I`. Если задана мощность:

- 1-фазная: `IB = P / (U · cosφ)`, где `U` — L-N (по умолчанию 230 В).
- 3-фазная: `IB = P / (√3 · U · cosφ)`, где `U` — линейное L-L (по умолчанию 400 В).

Ссылка: общая формула нагрузки; выбор сечения по IEC 60364-5-52, п. 523.

## 1.3 Выбор номинала аппарата In (IEC 60364-4-43, §433)

`In` выбирается из **дискретного стандартного ряда** как наименьший номинал `≥ IB`.
Ряд `In` (**реальный** отраслевой стандартный ряд номиналов — уникопирайтный факт, не
синтетика): 6, 10, 13, 16, 20, 25, 32, 40, 50, 63, 80, 100, 125, 160, 200, 250, 315, 400 А
(в норм-пакете). Обоснование каждого выбора фиксируется в трассе.

## 1.4 Пропускная способность кабеля IZ и поправки (IEC 60364-5-52)

`IZ = It · ka · kg · … `, где:

- **It** — табличное (опорное) значение для: метода прокладки (reference method A1…G,
  Табл. B.52.1), материала жилы (Cu/Al), изоляции (PVC/XLPE), числа нагруженных жил
  (2 или 3) и сечения. Таблицы токов — B.52.2…B.52.13 (иллюстративные значения в пакете).
- **ka** — поправка на температуру окружающей среды (Табл. B.52.14 для воздуха), зависит
  от изоляции и температуры. Опорная температура: **воздух 30 °C**, **земля 20 °C**.
- **kg** — поправка на группировку цепей (Табл. B.52.17 и далее), зависит от числа
  сгруппированных цепей и способа укладки.

**Критично:** все проверки сравниваются со **скорректированным** `IZ`, а трасса показывает
`It`, каждый множитель и итоговый `IZ` **раздельно** — иначе поправки не аудируемы.

## 1.5 Проверка (A): координация защиты от перегрузки (IEC 60364-4-43, §433.1)

Два условия одновременно:

1. `IB ≤ In ≤ IZ`
2. `I2 ≤ 1.45 · IZ`

где `I2` — ток, гарантирующий срабатывание аппарата в условное время (conventional
tripping current). **Ключевой нюанс по классу аппарата:**

| Класс аппарата | Стандарт | I2 / In | Следствие для второго условия |
|---|---|---|---|
| MCB (автомат) | IEC 60898 | **1.45** | `1.45·In ≤ 1.45·IZ` ⇒ сворачивается в `In ≤ IZ` (второе условие не связывает) |
| MCCB | IEC 60947-2 | ~**1.30** | `1.30·In ≤ 1.45·IZ` ⇒ `IZ ≥ 0.897·In` (не связывает) |
| gG предохранитель | IEC 60269 | **1.60** | `1.60·In ≤ 1.45·IZ` ⇒ **`IZ ≥ 1.103·In`** (связывает! требует большего кабеля) |

То есть для **gG-предохранителей** второе условие **активно** и часто заставляет выбрать
сечение больше, чем диктует простое `In ≤ IZ`. `I2/In` хранится в норм-пакете по классу.

Вывод условия для gG: `1.6·In ≤ 1.45·IZ` ⇒ `IZ ≥ (1.6/1.45)·In = 1.1034·In`.

## 1.6 Проверка (B): падение напряжения (IEC 60364-5-52, Прил. G — информативное)

Формула (сопротивление + реактанс жилы):

- 1-фазная: `ΔU = 2 · IB · L · ( ρ·cosφ / S + λ·sinφ )`
- 3-фазная: `ΔU = √3 · IB · L · ( ρ·cosφ / S + λ·sinφ )`

где:
- `ρ` — удельное сопротивление жилы при рабочей температуре («в эксплуатации»):
  Cu ≈ 0.0225, Al ≈ 0.036 Ω·мм²/м (иллюстративно; это ≈1.25× значения при 20 °C).
- `λ` — реактивное сопротивление на единицу длины ≈ 0.00008 Ω/м (типовой многожильный).
- `L` — длина трассы, м; `S` — сечение, мм².

`ΔU% = ΔU / U_nom · 100`. Предел (иллюстративно, по распространённой практике /
информативному Прил. G): **освещение 3 %**, **прочее/силовое 5 %**. Предел настраивается.

Допущение v1: установившийся режим; пусковые просадки двигателей не моделируются.

## 1.7 Проверка (C): термическая стойкость к КЗ — адиабатика (IEC 60364-4-43 §434.5.2 / -5-54)

`S ≥ I_scc · √t / k` ⇒ минимальное сечение `S_min = I_scc·√t / k`.

где:
- `I_scc` — действующий ток КЗ (прогнозный), А;
- `t` — время отключения, с;
- `k` — коэффициент материала/изоляции (A·√с/мм²), **синтетический** (не из IEC, `04`):

| Материал / изоляция | k (синтетика) |
|---|---|
| Cu / PVC | 120 |
| Cu / XLPE | 150 |
| Al / PVC | 80 |
| Al / XLPE | 100 |

Если `I_scc` не задан — проверка помечается `warning` и пропускается (не роняет расчёт),
явно фиксируясь в трассе как непроверенная.

## 1.8 Итоговый выбор и «governing constraint»

Кандидаты сечений перебираются по возрастанию стандартного ряда — но только **покрытые
данным паком** для запрошенной комбинации метод/материал/изоляция/жилы (реальный пак может
покрывать ряд частично, docs/04 §4.6; непокрытое сечение не является кандидатом). Для
каждого проверяются (A), (B), (C). Итог `S` — наименьшее покрытое сечение, проходящее **все**
активные проверки; если ни одно не проходит — `FAIL` на крупнейшем покрытом сечении.
`governing_constraint` (`overload_coordination` | `voltage_drop` | `short_circuit`) = критерий,
чей индивидуальный минимум сечения максимален. `overload_coordination` покрывает **оба**
подусловия (A): и `In≤IZ` (кейс 1), и `I2≤1.45·IZ` (кейс 2 — связал предохранитель); что
именно связало — фиксируется в детали шага. При равенстве приоритет: координация → КЗ → ВП.

## 1.9 Что делает результат аудируемым

1. **Трасса** — упорядоченный список шагов; каждый шаг: входы, формула, вычисление,
   результат, ссылки (Citation).
2. **Ссылки** — на реальные пункты/таблицы IEC (механизм прослеживаемости реален).
3. **Разделение значения/ссылки** — значения таблиц помечены `illustrative` и **синтетичны**
   (не из IEC); отчёт и README прямо заявляют: механизм цитирования полон и реален, а
   значения — синтетические до загрузки лицензионных данных, и PASS/FAIL отражают арифметику
   относительно синтетики, а не соответствие реальному стандарту (`04 §4.2`).
4. **Проверки** — явный список `Check` с булевым результатом и деталью.
5. **Подпись** — структурный `SignOff` (`UNSIGNED_ADVISORY` по умолчанию): без подписи
   инженера результат носит рекомендательный статус; система не сертифицирует.
