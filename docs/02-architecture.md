# 02 — Архитектура и потоки данных

## 2.1 Принцип

**Детерминированное ядро владеет числами. LLM оркестрирует, объясняет и перепроверяет,
но никогда не порождает числа.** Всё, что критично для корректности и прослеживаемости,
живёт в чистом, типизированном, тестируемом коде. LLM — слой поверх, отключаемый флагом.

## 2.3 Поток данных (основной сценарий)

```
                ┌─────────────── LLM-слой (опционален, флаг) ───────────────┐
NL-запрос ─▶ intake(Flash) ─▶ SizingRequest ─┐                              │
строгий ввод ───────────────────────────────┘                              │
                                              ▼                              │
                              ┌──────── ДЕТЕРМИНИРОВАННОЕ ЯДРО ────────┐     │
                              │ sizer.size(request):                  │     │
                              │  current → protection → ampacity      │     │
                              │  → voltage_drop → shortcircuit        │     │
                              │  → checks → SizingResult+AuditTrace   │     │
                              └───────────────┬───────────────────────┘     │
                                              ▼                              │
                    verify: детерм. чек-инварианты (ВСЕГДА) ──┐             │
                                              +               │             │
                    verify(Pro): независимая критика трассы ──┘ (если ключ) ─┘
                                              ▼
                    explain(Flash/Pro ИЛИ шаблон) ─▶ нарратив
                                              ▼
                    guardrails: числовой провенанс (нарратив ⊆ трасса)
                                              ▼
                    report → Markdown/JSON  (+ SignOff: UNSIGNED_ADVISORY)
                                              ▼
                    persistence → Neon | JSONL(./runs/)
```

## 2.4 Режимы работы

| Условие | Intake | Explain | Verify | Persist |
|---|---|---|---|---|
| Есть `OPENROUTER_API_KEY` | Flash (NL→spec) | Flash/Pro нарратив | Pro-критика **+** детерм. | по БД |
| Нет ключа (**фолбэк**) | только строгий ввод | шаблон | только детерм. | JSONL |
| Есть `DATABASE_URL` | — | — | — | Neon |
| Нет БД | — | — | — | JSONL `./runs/` |

**Инвариант D8:** ядро, проверки, тесты и E2E не зависят от ключа/БД. Фолбэк-режим —
полноценный (числа, проверки, трасса, отчёт, подпись); отсутствуют лишь NL-разбор и
LLM-нарратив/критика, которые заменяются строгим вводом, шаблоном и детерм. проверкой.

## 2.5 Гардрейлы (`guardrails.py`)

1. **Числовой провенанс.** Из нарратива LLM извлекаются все числовые токены; каждый обязан
   присутствовать в трассе (со списком допусков округления). Нарушение → при
   `ELECTRICOPILOT_STRICT_PROVENANCE=true` отчёт → `NEEDS_REVIEW` (через
   `apply_provenance_downgrade`, возвращающий копию), нарратив помечается непроверенным;
   отклонённые числа перечисляются.
2. **Инвариант подписи.** `SizingResult` всегда содержит `SignOff`; по умолчанию
   `UNSIGNED_ADVISORY`. Отчёт физически не может быть выпущен «сертифицированным».
3. **Дисклеймер.** Константный текст «рекомендация, не сертификация; требуется проверка и
   подпись квалифицированного инженера» встраивается в каждый отчёт.
4. **Инварианты движка.** Пост-условия: `IB ≤ In ≤ IZ` при `PASS`; `IZ = It·∏k` (сверка);
   выбранное `S` реально проходит все активные проверки; `governing_constraint` согласован.

## 2.6 Ошибки и деградация

- Неизвестный slug модели → `LlmConfigError` с явным сообщением (не молчаливый фолбэк, D10).
- LLM-таймаут/сбой при живом ключе → падаем на шаблон объяснения, помечаем `warning`, но
  **числа не трогаем** (они уже посчитаны детерминированно).
- Вход вне поддерживаемого множества (метод/материал/изоляция/число жил) → `ValidationError`
  с перечислением допустимых значений (без «угадывания», по совету advisor).
- Значение отсутствует в таблице для запрошенного сечения → явная ошибка загрузчика данных.

## 2.7 Технологический стек

- Python 3.11+; `pydantic` v2 (контракты/валидация); `httpx` (OpenRouter REST);
  `typer`+`rich` (CLI/вывод); `python-dotenv` (env). Dev: `pytest`, `ruff`, `mypy`.
- Опц.: `sqlalchemy`+`psycopg` (Neon); `fastapi`+`uvicorn` (HTTP). Extras в `pyproject.toml`.
