# ТЗ 20 — Нормативная библиотека (фаза v4, скоуп «электрика»)

Статус: спека, заморожена до начала работ. Ветка исполнения — `feat/v4-norm-library` от `main`.
Процесс — правило 4 CLAUDE.md: 1 фаза = 1 сессия = 1 ветка, в конце PR, СТОП до подтверждения
заказчика. Перед PR — `/code-review high`.

Заказчик сформулировал направление так: «использовать наработки проекта legality, чтобы все
нормативы загрузить и чтобы инженерам было удобно всё смотреть в студии; пока — для электриков».
Расширение на другие строительные дисциплины — отдельное решение, в этой фазе не проектируется
(корпус спроектирован так, чтобы добавление дисциплины было добавлением строк в реестр, а не
переписыванием схемы).

## 0. Что это и чем НЕ является

**Является:** читалкой и поиском по официальным текстам норм внутри Studio, с постоянными
ссылками на конкретный пункт и с привязкой цитат расчётного ядра к тексту нормы.

**НЕ является:**
- источником чисел для расчёта. Числа по-прежнему берутся ТОЛЬКО из датапаков, извлечённых
  кодом (`scripts/extract_pue_rk.py`), и принцип 1 CLAUDE.md не ослабляется: LLM не считает.
  Текст нормы в библиотеке — для человека, не для движка;
- автоматическим извлечением новых таблиц в паки (это отдельная фаза, см. §11);
- юридической консультацией: статус «рекомендательно, не сертификация» сохраняется.

## 1. Разведка источника (выполнена 2026-07-28, живьём)

Всё ниже проверено фетчем `https://adilet.zan.kz/rus/docs/{ID}` и парсингом HTML, не по памяти.

| ID | Документ | Статус | Текст, симв. | `<table>` | z-якорей |
|---|---|---|---|---|---|
| `V1500010851` | Правила устройства электроустановок (ПУЭ РК) | в силе | 1 646 347 | 250 | 11 222 |
| `V1500010949` | Правила технической эксплуатации электроустановок потребителей | в силе | 296 657 | 2 | 833 |
| `V1600014771` | НТД в области электроэнергетики и теплоэнергетики | в силе | 1 857 906 | 656 | 21 062 |
| `V2300032783` | Техрегламент «О безопасности зданий и сооружений…» | в силе | 323 601 | 16 | 269 |

Ключевые выводы разведки:

1. **Якоря `z\d+` реальные и плотные** — `#z24` в URL ведёт в конкретный пункт на сайте
   первоисточника. Это даёт постоянную ссылку «цитата → пункт нормы» без нашей нумерации.
2. **Граф ссылок работает как навигация по редакциям.** Действующий акт находится по ссылке
   из отменённого: со страницы `V1900019361` («Утратил силу приказом … № 153-НҚ») извлекается
   `/rus/docs/V2300033579#z24`. Резолвить ID через граф, НИКОГДА не из памяти модели.
3. **⚠ Действующих СН РК/СП РК по электрике на adilet НЕТ.** Приказ 153-НҚ (`V2300033579`)
   на adilet — это только «О признании утратившими силу некоторых приказов»; он отменил
   СН РК 4.04-04/07/08-2019, а тексты редакций 2023 на adilet не опубликованы — п. 2 приказа
   отправляет их на интернет-ресурс Комитета, фактический доступ — ЕГФ НТД (КазСтандарт,
   платно) и коммерческие базы (Параграф). Редакции 2019 на adilet есть полным текстом
   (`V1900019361`, 294 тыс. симв.), но **утратили силу**.

   Следствие для скоупа: корпус v1 состоит из актов Минэнерго и техрегламента (таблица выше).
   СН РК/СП РК в v1 **не входят** — показывать инженеру утративший силу документ как норму
   вреднее, чем не показывать ничего. Задача «легально получить действующие СН/СП РК» —
   отдельная, продуктово-юридическая, вынесена в §11.
4. **Compliance.** `robots.txt` adilet запрещает `/rus/search/`, `/rus/list/docs/`, `/files/`;
   `/rus/docs/{ID}` не запрещён. Поэтому в этой фазе **поисковый эндпоинт adilet не
   используется вообще**: реестр ID хранится в репозитории, новые ID резолвятся через граф
   ссылок уже загруженных документов. Изменение этой политики — явное решение заказчика,
   а не побочный эффект реализации.

## 2. Что берём из legality (и чего не берём)

`~/vibecode/legality` — приватный репозиторий Олжаса. **Переиспользуется дизайн, а не код**;
копирование исходников оттуда — вопрос к владельцу репозитория, и в этой фазе не требуется.

Не берём: HTTP-фетчер и парсер. Они уже есть в Python в `scripts/extract_pue_rk.py`, включая
обход оборванной TLS-цепочки adilet через curl-фолбэк (в legality тот же костыль описан в
`lib/adilet.ts`). Дублировать нечего — этот код выносится в `src/` (см. §4).

Берём как проверенные другим проектом решения:

| Решение legality | Как применяем |
|---|---|
| Модель корпуса `Document → ChunkSet → Chunk(parent+leaf)` с «breadcrumb-baked» контентом | упрощаем до `norm_documents → norm_sections` (двух уровней достаточно на 4 документа), но сохраняем хлебные крошки в тексте секции — они несут контекст при поиске |
| Граф `Document.links` как первый способ найти документ (до всякого поиска) | `norm_links`, заполняется парсером; это наш легальный способ резолвить редакции (§1.2) |
| Вывод «fulltext-ранжированию источника доверять нельзя; реальный порядок делает reranker» | не тащим векторный стек ради 4 документов: лексический поиск + опциональный LLM-реранк top-30 (§6) |
| `CHAT_GROUNDING_TRANSFORM` — ответ проходит, только если цитаты ведут в реальный `docId`/якорь | обязательный гардрейл ответов читалки (§8) |
| `NAMED_LAW_ABSENCE_RULE` — нет документа в корпусе ⇒ честная абстенция | переносится дословно по смыслу (§8) |
| Статус документа как первоклассное поле (в силе / утратил силу) с бейджем в UI | обязательно: §1.3 — половина найденного по электрике утратила силу |

## 3. Модель данных (Neon Postgres)

Новый модуль `src/electricopilot/norms/store.py`, стиль — как `store.py` фазы 4 (DDL строкой,
`psycopg`, idempotent upsert). Без ORM.

```sql
CREATE TABLE IF NOT EXISTS norm_documents (
    id            TEXT PRIMARY KEY,          -- adilet ID, напр. 'V1500010851'
    title         TEXT NOT NULL,
    kind          TEXT NOT NULL,             -- 'pue' | 'ptee' | 'ntd' | 'techreg'
    discipline    TEXT NOT NULL DEFAULT 'electrical',
    status        TEXT NOT NULL,             -- 'in_force' | 'repealed' | 'unknown'
    status_note   TEXT,                      -- дословная сноска источника об утрате силы
    source_url    TEXT NOT NULL,
    fetched_at    TIMESTAMPTZ NOT NULL,
    content_sha256 TEXT NOT NULL,            -- sha256 нормализованного текста документа
    meta          JSONB NOT NULL DEFAULT '{}'
);

CREATE TABLE IF NOT EXISTS norm_sections (
    id          TEXT PRIMARY KEY,            -- '{doc_id}#{anchor}', напр. 'V1500010851#z1204'
    doc_id      TEXT NOT NULL REFERENCES norm_documents(id) ON DELETE CASCADE,
    anchor      TEXT NOT NULL,               -- 'z1204'
    ordinal     INTEGER NOT NULL,            -- порядок в документе, для навигации
    breadcrumb  TEXT NOT NULL,               -- 'Глава 2 › Параграф 3'
    heading     TEXT,
    body        TEXT NOT NULL,               -- нормализованный текст пункта
    has_table   BOOLEAN NOT NULL DEFAULT FALSE,
    tsv         tsvector GENERATED ALWAYS AS (
                    to_tsvector('russian', coalesce(breadcrumb,'') || ' ' ||
                                           coalesce(heading,'')    || ' ' || body)
                ) STORED
);
CREATE INDEX IF NOT EXISTS norm_sections_tsv_idx  ON norm_sections USING GIN (tsv);
CREATE INDEX IF NOT EXISTS norm_sections_doc_idx  ON norm_sections (doc_id, ordinal);

CREATE TABLE IF NOT EXISTS norm_links (
    from_doc TEXT NOT NULL REFERENCES norm_documents(id) ON DELETE CASCADE,
    to_doc   TEXT NOT NULL,                  -- может отсутствовать в корпусе — это нормально
    anchor   TEXT,
    PRIMARY KEY (from_doc, to_doc, anchor)
);
```

Офлайн-режим (без `DATABASE_URL`) обязателен, как во всём проекте: тот же интерфейс поверх
JSON-снапшотов в `./runs/norms/` — иначе тесты и локальная разработка требуют БД, что
запрещено правилами окружения.

## 4. Ingest-пайплайн

Новый `src/electricopilot/norms/ingest.py` + CLI `uv run electricopilot norms ingest [ID…]`.

1. **Fetch.** Вынести из `scripts/extract_pue_rk.py` в `src/electricopilot/norms/fetch.py`
   функции загрузки (httpx → curl-фолбэк по TLS, User-Agent, таймаут). `extract_pue_rk.py`
   после этого импортирует их оттуда — дублирования быть не должно.
   Кэш HTML — в `./runs/norms-cache/` (в git не попадает).
2. **Гейт целостности.** Аналог `looksContentless` из legality: если ответ короче 20 КБ, не
   содержит `Назад к документу` или z-якорей — считать загрузку неуспешной и не перезаписывать
   уже сохранённую версию (защита от заглушек/капчи).
3. **Parse.** `src/electricopilot/norms/parse.py`: HTML → `NormDocument` + список `NormSection`.
   Разбиение — по z-якорям (они в источнике стоят на пунктах), хлебные крошки собираются из
   ближайших предшествующих заголовков «Глава N.» / «Параграф N.» / «Приложение N».
   Таблицы: сохранять как размеченный текст (`|`-разделители) и ставить `has_table=true`;
   HTML-разметку в БД не тащить.
4. **Статус.** Определяется по сноске первоисточника: наличие «Утратил силу приказом …» →
   `repealed` + дословный текст сноски в `status_note`. Отсутствие явной сноски → `in_force`.
   Никаких эвристик по датам.
5. **Links.** Все `/rus/docs/{ID}` из тела документа → `norm_links` (это механизм резолва
   редакций из §1.2).
6. **Upsert идемпотентный** по `id`; `content_sha256` меняется ⇒ секции документа
   перезаписываются целиком в одной транзакции (никаких частичных состояний).
7. **Реестр корпуса** — `src/electricopilot/norms/registry.json`, коммитится: список ID,
   ожидаемый вид, дисциплина, зачем документ в корпусе. Ingest без аргументов идёт по реестру.
   Документ вне реестра не грузится (защита от неконтролируемого разрастания и от обхода §1.4).

## 5. Детерминированность

Инвариант проекта (байт-детерминированный экспорт) распространяется на ingest:
одинаковый входной HTML ⇒ одинаковые секции, одинаковый `content_sha256`. Нормализация:
NFC, схлопывание пробелов, ` ` → пробел, удаление служебной обвязки сайта (шапка, меню,
«Вернуться в мобильную версию» и т. п.) по явному списку селекторов, а не по эвристике.
Тест: два прогона парсера на одной фикстуре дают идентичный JSON-дамп.

## 6. Поиск

**v1 — лексический, без векторов.** Обоснование: корпус — 4 документа (в legality 2 727), а
измеренный там выигрыш гибрида (+12 п.п. anchor@30) достигался на масштабе, которого здесь нет;
реальный порядок в обоих случаях делает переранжирование, а не арм поиска. Тащить эмбеддинги,
pgvector и HNSW ради 4 документов — преждевременная сложность.

```
POST /api/norms/search  {query, doc_ids?, limit=20}
  → ranked[] {section_id, doc_id, anchor, breadcrumb, heading, snippet, rank, doc_status}
```
Реализация: `ts_rank_cd(tsv, websearch_to_tsquery('russian', :q))`, подсветка через
`ts_headline`. Секции документов со статусом `repealed` возвращаются только при явном
`include_repealed=true`; по умолчанию скрыты.

**Опциональный реранк** за флагом `NORMS_LLM_RERANK=1`: топ-30 заголовков+сниппетов уходят
в быструю модель (`google/gemini-3-flash-preview`), она возвращает ТОЛЬКО переупорядоченный
список идентификаторов секций. Любой ответ, содержащий что-то кроме известных `section_id`,
отбрасывается целиком, порядок остаётся лексическим. Модель здесь не пишет текст и не трогает
числа — она сортирует.

## 8. Гардрейлы (обязательны, из legality)

1. **Цитатное заземление.** Любой текст, который Studio показывает как норму, обязан нести
   `doc_id` + `anchor` + `source_url#anchor`. Секция без якоря не отображается как цитата.
2. **Абстенция.** Если запрошенный акт отсутствует в корпусе — ответ «документа нет в
   библиотеке» со списком того, что есть. Запрещено: пересказывать норму по памяти модели,
   догадываться о номере пункта, подставлять похожий документ.
3. **Разделение числа и текста.** LLM-объяснение (`llm/explain.py`) может цитировать секции
   библиотеки, но провенанс-гардрейл `guardrails.py` продолжает сверять все числа в тексте
   с числами ядра. Числа из текста нормы в расчёт не попадают ни при каких условиях.
4. **Статус в лицо.** Бейдж статуса документа виден везде, где показан его текст. Для
   `repealed` — плашка с дословной сноской об утрате силы.

## 9. Интеграция с расчётом — ради чего всё

Сегодня `Citation` (`models.py:34`) несёт `standard/clause/table/edition/note` — человекочитаемо,
но никуда не ведёт. Расширяем **опциональными** полями, обратная совместимость обязательна:

```python
class Citation(BaseModel):
    standard: str
    clause: str | None = None
    table: str | None = None
    edition: str | None = None
    note: str | None = None
    doc_id: str | None = None      # 'V1500010851'
    anchor: str | None = None      # 'z1204'
```

- В `pue-rk.json` у разделов уже есть `_citation.source_url` — добавить `doc_id`/`anchor`
  туда, где пункт однозначно определён (напр. `grouping_correction` → п. 40 Правил).
  Значения проставляются **скриптом-резолвером по загруженному тексту** (поиск точной
  формулировки пункта), а не руками и не моделью; несопоставленное остаётся `None`.
- В отчёте и карточках нормоконтроля цитата с `doc_id`+`anchor` становится ссылкой
  «открыть пункт» → читалка Studio; без якоря рендерится как сегодня.
- Это и есть заявленная ценность: аудит-трасса доходит не до названия стандарта, а до текста.

## 11. Явно вне скоупа этой фазы

- Действующие СН РК/СП РК (редакции 2023+): недоступны на adilet (§1.3). Варианты — запрос
  в Комитет, подписка ЕГФ НТД/КазСтандарт, лицензия Параграфа — это решение заказчика с
  бюджетом и правами, отдельной задачей.
- Другие дисциплины (ОВиК, ВК, конструкции): схема к ним готова (`discipline`), наполнение —
  после решения по §11.1, так как упирается в тот же источник.
- Автоизвлечение таблиц норм в датапаки (расширение `extract_pue_rk.py` на 250 таблиц ПУЭ):
  отдельная фаза; в этой ingest сохраняет таблицы как текст для чтения человеком, и только.
- Векторный поиск/эмбеддинги (§6), поиск через `/rus/search/` adilet (§1.4), казахская
  локаль корпуса.

## 12. Приёмка

1. `uv run pytest` — зелёные, **без сети и без БД**: парсер тестируется на обрезанных
   HTML-фикстурах в `tests/fixtures/norms/` (по одному фрагменту на документ корпуса,
   ≤ 200 КБ каждый), store — на офлайн-бэкенде.
2. Тест детерминированности: два прогона парсера на фикстуре → идентичный JSON (§5).
3. Тест статуса: фикстура с «Утратил силу приказом …» → `status='repealed'` + непустой
   `status_note`; фикстура ПУЭ → `in_force`.
4. Тест абстенции: `/api/norms/{неизвестный}` → 404 с типизированным телом; поиск по пустому
   корпусу → пустой список, а не выдуманный результат.
5. Тест обратной совместимости `Citation`: существующие golden-кейсы отчёта и экспорта не
   меняют байты (`doc_id`/`anchor` = `None` не сериализуются в отличие от текущего вывода —
   проверить и, если сериализуются, исключить через `exclude_none`).
6. `uv run ruff check .`, `uv run mypy src` (strict) — чисто.
7. Ручная проверка на реальном корпусе (вне CI): `uv run electricopilot norms ingest` грузит
   4 документа реестра; в Studio ищется «падение напряжения» и «сечение нулевого рабочего
   проводника», результат ведёт в правильный пункт ПУЭ на adilet.
