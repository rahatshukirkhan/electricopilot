# Дизайн-спека v2 «Navy & Burgundy» — полная пересборка UI/UX Studio

Утверждено заказчиком: сайдбар остаётся, светлая тема, палитра navy + burgundy,
навигацию упростить («слишком много деталей»), UI/UX поменять полностью.
База — ветка `design/proto-c` (сайдбар уже есть). Эта спека — источник истины;
при неоднозначности исполнитель следует ей, а не привычкам.

## 1. Токены

### Цвет (только светлая тема)
```
--paper:    #FAF9F6   фон рабочего поля (тёплая бумага)
--card:     #FFFFFF   панели/карточки
--wash:     #F1EFE9   вставки, hover, table header
--line:     #E5E1D8   границы
--line-2:   #D3CDBF   сильные границы/разделители

--ink:      #1C2536   основной текст (тёмный navy-чернильный)
--dim:      #5A6478   вторичный текст
--faint:    #8B93A5   третичный/подсказки

--navy:     #24407A   интерактив: кнопки, ссылки, активные состояния, фокус
--navy-press:#1B3161  нажатие
--navy-soft:rgba(36,64,122,.09)

--burgundy: #7E2440   акцент бренда: главный CTA экрана, активный пункт сайдбара
                      (полоска), ключевые числа в итогах, выделения
--burgundy-press:#66192F
--burgundy-soft:rgba(126,36,64,.08)

Сайдбар: фон #182338 (глубокий navy), текст #C4CBDA, активный пункт — фон
rgba(255,255,255,.06) + полоска --burgundy слева, текст #FFFFFF.

Статусы (НЕ пересекаются с burgundy — ошибка холоднее и ярче):
--ok:#2E7D4F  --warn:#A9701E  --bad:#C8321F
+ soft-подложки rgba(...,.10). Пилюли статусов компактные.
```
Контраст текста всюду ≥ 4.5:1 (проверять руками спорные пары: dim на wash,
warn на white, текст сайдбара).

### Типографика
IBM Plex суперсемейство (Google Fonts): **IBM Plex Serif** (600) — только
заголовки экранов h1/h2 и названия щитов; **IBM Plex Sans** — весь UI;
**IBM Plex Mono** — числа, ref, коды, бейджи. Serif — характер «инженерного
журнала», по чуть-чуть: НЕ в кнопках, НЕ в таблицах, НЕ в панельных заголовках.
Заголовок экрана 26–28px/600 serif; панельные заголовки 12.5px/600 sans без
капса; таблицы 13.5px; body 14px/1.55. tabular-nums для чисел.

### Форма
Радиусы: 6px (кнопки/инпуты), 10px (карточки/панели). Тени: одна тихая
`0 1px 2px rgba(28,37,54,.05)` на карточках; заметная — только у dropdown,
поповеров, тоста. Никакой миллиметровки и градиентов.

## 2. Логика навигации (ГЛАВНОЕ упрощение)

1. **Сайдбар** (240px, navy): вверху бренд (болт-иконка + «ElectriCopilot»,
   sans 15px/600, «Studio» убрать вовсе — деталь-шум); навигация: «Щиты»
   (id=homeLink), «Нормы» (id=btnNorms); внизу ОДНА тихая строка статуса,
   объединяющая #modeTag и #saveState (12px, faint) — никаких двух строк
   и точек-светофоров. Крошек в сайдбаре нет.
2. **Крошки-дубли убрать.** Глобальный #crumbs остаётся в DOM (JS-контракт),
   но рендерится как ОДИН элемент «← Назад-контекст»: на экране щита —
   «← Щиты», в редакторе — «← Щит ВРУ-1», в нормах — «← Щиты». Функцию
   crumbs() в app.js переписать под это (последний элемент-название не
   показывать — название уже в h1 экрана). Кнопки btnBackDash/btnBackPanel
   из UI убрать (hidden, в DOM остаются).
3. **Один статус на экран.** #statusBadge в топбаре скрыть навсегда (hidden,
   в DOM остаётся); статус живёт только у объекта: у названия щита, в строке
   цепи, у карточки. Топбар рабочей зоны становится тонкой строкой: «← Назад»
   слева, справа НИЧЕГО (пусто) — или вовсе сливается с фоном.
4. **Шапка щита — минимум деталей.** Первая строка: название (serif, inline-edit
   как сейчас) + статус-пилюля щита (#boardRollup). Вторая строка — ОДНА тихая
   строка метаданных: `DB-1 · Эл.щитовая · 400 В · 3ф · TN-C-S · 12 мест ·
   IEC 60364 (демо)` — редактирование по клику: раскрывается компактный
   попап/строка с инпутами (b_ref, b_location, b_pack — те же id, можно
   держать их в скрытом контейнере и показывать по кнопке «Параметры щита»).
   Бейдж пака (#b_packStatus) — внутрь попапа, из шапки убрать.
   Действия: **«Нормоконтроль» (burgundy primary)** + «Пакет документов»
   (navy secondary) + «Ещё ⋯» (Share, Печать, Отчёт, Файл проекта).
   Share из шапки убрать в «Ещё» — e2e-тесты обнови (добавь клик по «Ещё»,
   как сделано в ветке design/proto-b — можно подсмотреть коммит fc5e15e).
5. **Дашборд.** Заголовок «Щиты» (serif). Действия: «+ Новый щит» (burgundy
   primary), поиск; «Загрузить пример», «Импорт из XLSX/CSV», «Открыть файл»
   — в одно меню «Ещё». Карточка: название (serif 17px), ref моно-чипом,
   ОДНА строка статуса («4 цепи · 4 требуют проверки» — счётчики словами,
   не 4 разноцветных чипа; цвет — точкой перед худшим статусом), дата тихо,
   kebab «⋯». Пустое состояние — дружелюбное, с одной кнопкой.
6. **Редактор цепи.** Бар: «← Щит …» + ref-навигация (пред/след) + статус
   подписи + «Подписать цепь» + «Сохранить в щит» (burgundy). Правая колонка:
   «Копилот» и «Обоснование расчёта» — ВКЛАДКИ одной панели (меньше
   одновременных деталей; обе DOM-секции живут, переключение display).
   Сводка (#summary) — спокойная строка ключ-значение, «Определяет:» выделить.
7. **Библиотека норм** — та же трёхколонка, перекрасить в токены; активный
   документ — burgundy-полоска (как в сайдбаре); статус «действует» — ok-пилюля.
8. **Advisory** — тонкая строка 26px на wash-фоне с amber-текстом, без бордеров
   сверху и снизу лишних. Одна на всё приложение, как сейчас.

## 3. Графики и SLD

Plotly BASE: font --dim, grid #ECE9E1; кривая кабеля — #C8321F; полоса
аппарата/выбранные элементы — --navy; выбранное сечение в подборе — --burgundy,
проходящие — приглушённый ok, непроходящие — #D8D3C7. Клиентский SLD
(renderSLD): контуры --ink, статусный цвет рамки, подписи mono.
**Серверный SLD-SVG** (src/electricopilot/export/svg.py и связанные):
перекрасить в ту же палитру (navy контуры, burgundy для итогового узла-статуса
не использовать — статусные цвета ok/warn/bad как в токенах). Тесты экспорта
(детерминизм/снапшоты) обновить соответственно. Печать/DXF остаются как есть
(DXF — цветовые индексы, не трогать).

## 4. Жёсткие контракты

- Все id и data-атрибуты сохраняются в DOM (перемещать можно, удалять нельзя).
- Классы, на которые опирается логика app.js (.tabs button.active, .msg,
  .st-cell.<STATUS>, .norm-*, .nlib-*, .save) — имена сохранить; namespace-тесты
  tests/test_norms_api.py должны проходить (при необходимости правь тесты
  осознанно, но префиксы норм-библиотеки ломать запрещено).
- Русские тексты интерфейса не менять, КРОМЕ явно указанных упрощений
  (напр. «Проекты — щиты» → «Щиты»; «Проекты» в сайдбаре → «Щиты»);
  каждое изменение текста — проверить, не ждёт ли его e2e, и обновить тест.
- Печатная страница — бумажная, сайдбар на печати скрыт.
- Тесты: `uv run pytest`, `uv run ruff check .`, `uv run mypy src`, browser e2e
  (`mv .env .env.bak && ELECTRICOPILOT_BROWSER_E2E=1 uv run pytest -m browser_e2e;
  mv .env.bak .env`) — всё зелёное перед завершением каждой фазы.

## 5. Definition of done

Экраны: дашборд (пустой + с карточками), щит (таблица, итоги, копилот,
нормоконтроль с запуском), редактор (все 5 вкладок графиков), нормы
(список/поиск/читалка/боковая панель цитаты), печать, share — все в новой
системе, без сырых остатков старой палитры (кроме печати), консоль браузера
чистая, 1512×900 и 1280×720 без горизонтального скролла страницы.
