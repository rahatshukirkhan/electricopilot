# ТЗ 17 — Язык электрика и UX-полировка Studio

Статус: спека для исполнения на ветке `feat/design-blueprint-light` (поверх ТЗ 16). Исполнитель следует буквально; неоднозначность — СТОП и вопрос. Причина: заказчик отверг текущие вординги («для программистов, а не для электриков») и UX-простыню формы.

## 1. Принцип

Целевой пользователь — проектировщик-электрик. Весь видимый текст — профессиональный русский (терминология ПУЭ/ГОСТ). Сырые enum, snake_case-идентификаторы и дев-информация в интерфейсе запрещены. **Русификация — только слой отображения**: значения enum в API-запросах/ответах, localStorage, экспортах и `value=` селектов НЕ меняются. Инженерная нотация сохраняется как есть: IB, IZ, In, IΔn, ΔU, cosφ, TN-C-S, методы прокладки A1–G, Cu/Al, PVC/XLPE, MCB/MCCB, kA.

## 2. Границы

- Менять: `web/app.js` (слой отображения + словарь), `web/index.html` (тексты, структура формы редактора, атрибуты title), `web/styles.css` (новые классы для групп формы и вторичных кнопок; имена существующих классов/id/переменных не переименовывать).
- Не трогать: `src/**`, `api/**`, `tests/**`; логику расчётов/fetch/localStorage; печатные и файловые экспорты серверной стороны.
- CSS-классы статусов (`.st-cell.PASS` и т.п.) остаются привязанными к enum — меняется только текст внутри элемента.

## 3. Словарь отображения (единая функция-словарь в app.js)

Добавить в app.js словарь и функции `stLabel(status)`, `govLabel(g)` и применить ВЕЗДЕ, где значения показываются пользователю (чипы таблицы, бейджи топбара/щита/редактора, карточки дашборда, share-экран, печатная страница, тултипы тостов). Каждый чип/бейдж получает `title` с техническим кодом (выбор заказчика: «русская метка + код в тултипе»).

Статусы:
| Код | Метка |
|---|---|
| PASS | Соответствует |
| FAIL | Не проходит |
| NEEDS_REVIEW | Требует проверки |
| UNSIGNED_ADVISORY | Не подписано · рекомендательно |
| SIGNED | Подписано |
| READ-ONLY (share) | Только просмотр |

Определяющий критерий (`governing`, значения из `engine/sizer.py:_PRIORITY`):
| Код | Метка |
|---|---|
| overload_coordination | координация по перегрузке |
| short_circuit | термическая стойкость к КЗ |
| voltage_drop | падение напряжения |

Сводка редактора: `СВЯЗЫВАЕТ: overload_coordination` → `Определяет: координация по перегрузке` (+title с кодом). Заголовок свипа `(overload_coordination)` → русская метка. Неизвестный код → показать как есть (не падать).

## 4. Замены текстов (index.html и строки в app.js)

Заголовки соответствующих графиков в app.js привести к тем же формулировкам («Свип сечения — выбрано…» → «Подбор сечения — выбрано…», «Дерейтинг: It → IZ…» → «Поправочные коэффициенты: It → IZ…»).

- Селект назначения (`f_purpose`): value остаются lighting/power/socket/motor/general, отображаемый текст: «освещение / силовая / розетки / двигатель / прочее».
- Норм-пакеты в селекте `b_pack`: value не менять; текст: `iec-stub` → «IEC 60364 (демо-данные)», `pue-rk` → «ПУЭ РК (adilet)»; версию оставить.
- Импорт: «Сопоставление колонок» остаётся; все вхождения «mapping» в видимых текстах → «сопоставление»; «assumptions» → «допущения»; «Пересчитать с этим mapping» → «Пересчитать с этим сопоставлением»; чекбокс: «Я проверил сопоставление колонок и подтверждаю отмеченные допущения. - «Экспорт .ecproj» → «Сохранить файл проекта»; label «Импорт .ecproj.json» → «Открыть файл проекта»; «Импортировать щит XLSX/CSV» → «Импорт щита из XLSX/CSV». Имена скачиваемых файлов не менять.

- Share-экран: бейдж «READ-ONLY · UNSIGNED_ADVISORY» → «Только просмотр · не подписано» (+title); текст предупреждения оставить.
- Дисклеймер норм-пакета (app.js, где перечисляются секции standard_ratings, …): русские названия секций: номинальные ряды аппаратов; стандартные сечения; параметры аппаратов; правило перегрузки; пропускная способность; поправка на температуру; поправка на группировку; коэффициент адиабаты k; удельные сопротивления; реактансы; предел ΔU.
