## 2. Принципы (фильтр для любых новых идей)

- **P1. Один источник истины:** любой пиксель — производная `SizingResult`/report.
- **P2. График = ответ на один рабочий вопрос инженера.** Нет вопроса — нет графика.
- **P3. Кликабельность до нормы:** любой элемент → шаг трассы → пункт документа.
- **P4. Провенанс-маркировка на каждой фигуре** (illustrative / public_standard).
- **P5. Интерактив = мгновенный детерминированный пересчёт,** не анимация ради красоты.
- **P6. Всё, что видно на экране, должно уметь печататься** (light-тема, SVG).

## 3. Визуализации: что добавить

### 3.1 Уровень цепи

- **V1. «Линейка координации» (приоритет №1).** Горизонтальная числовая ось с
  метками IB → In → IZ → 1.45·IZ и подписанными зазорами в % между ними.
  Вопрос: «почему выбран этот аппарат и сколько запаса». Это САМАЯ понятная
  визуализация всей предметной области — понятнее TCC для 90% случаев. Простой SVG
  (не Plotly), рендерится и в печатной форме, и в отчёте. Данные уже есть в result.
- **V2. Слайдеры «что-если» + границы применимости.** Слайдеры длины / температуры /
  группировки с live-пересчётом (debounce уже есть). Плюс новый viz-блок `limits`:
  обратная задача бинарным поиском по движку — «текущее сечение держит до **31 м**
  (запас 11 м)», «при 45 °C потребуется 6 мм²». Вопрос: «сколько у меня запаса».
  Значения вне таблиц пака показывать серой зоной «нет данных» (off-table политика
  движка уже честная — визуализировать её).
- **V3. TCC-улучшения:** hover с точными временами; после Ф3 (появится
  `supply.incomer`) — вторая полоса вышестоящего аппарата для визуальной селективности.
- **V4. Свип + деньги (после Ф6):** вторая ось — стоимость кабеля на длину цепи.
  Вопрос: «сколько стоит перестраховка сечением». Продающая фигура для заказчиков.
- **V5. Кумулятивное ΔU (после Ф3 R03):** стек «фидер + цепь» против лимита.

### 3.2 Уровень щита

- **V6. Полная интерактивная однолинейка щита.** Прямой реюз `SLDModel` из Ф2
  (docs/12): те же примитивы → SVG на экран, клик по аппарату → редактор цепи,
  цвет = статус. Один рендер обслуживает экран, печать и DXF. Мини-SLD цепи удалить.
- **V7. Фазовый баланс 2.0.** Стек-бары L1/L2/L3 с сегментами-цепями; **drag&drop
  цепи на другую фазу** с мгновенным пересчётом перекоса. Вопрос: «как выровнять
  фазы» — сейчас инженеры делают это перебором в Excel. Киллер-интерактив щита.
- **V8. Матрица здоровья.** Строки — цепи, колонки — проверки, ячейка — запас в %
  (тепловая карта: зелёный 30%+ … красный <5%/FAIL). Вопрос: «где тонко». Даёт
  взгляд на щит одним экраном; клик по ячейке → соответствующий шаг трассы.
- **V9. Загрузка ввода (после Ф3):** линейка/gauge — расчётный ток щита vs номинал
  вводного аппарата.
- **V10. Панель нормоконтроля (Ф3):** findings с severity, hover ↔ подсветка строк
  schedule и элементов однолинейки V6.

### 3.3 Анти-список (не делать)

Sankey потоков мощности, 3D-щиты, анимации, «цифровой двойник» на планировке —
эффектно на скриншотах, не отвечает ни на один рабочий вопрос при текущем слое
данных (нет геометрии здания). Вернуться только после CAD-импорта (v4+).

## 4. Интерактив: сквозные паттерны

- **Cross-highlight:** hover на строке schedule ↔ подсветка на V6/V7/V8 и обратно.
- **Трасса как хаб:** из любой фигуры клик ведёт к шагу трассы; в трассе у каждой
  цитаты — иконка-ссылка на официальный источник пака (для `pue-rk` — прямой URL
  на adilet с якорем таблицы).
- **Undo-паттерн** (тосты с «Отменить» уже есть) распространить на правки формы и
  применение proposal из копилота (снапшот до применения).
- **Клавиатура:** ↑/↓ по цепям щита, Enter — редактор, Esc — назад. Инженеры за
  таблицами живут на клавиатуре.

## 5. MCP и интеграции

### 5.1 ElectriCopilot КАК MCP-сервер (стратегический ход)

Обернуть существующие функции в MCP-tools (`fastmcp` поверх тех же вызовов, что
studio_api): `size_circuit`, `project_report`, `normcheck`, `list_packs`, `explain`.
~1 день работы, эффект: **любой Claude-клиент** (Desktop / Code / claude.ai) становится
клиентом продукта — инженер прямо в чате получает аудируемые числа с цитатами вместо
галлюцинаций модели. Дистрибуция через каталоги MCP-серверов бесплатна. Мы для
экосистемы ИИ — то же, чем коннекторы Claude Science являются для науки.

## 6. Форматы выдачи результата (слоёная модель)

| Слой | Форма | Сценарий |
|---|---|---|
| F1 | Экран Studio (интерактив) | работа инженера |
| F2 | Share-ссылка read-only (Ф4) | согласование с ГИП/заказчиком |
| F3 | Печатная форма → PDF браузером (Ф2) | подшивка, архив |
| F4 | ZIP-пакет: MD + DXF + SVG + XLSX×2 + JSON (Ф2) | передача смежникам |
| F5 | JSON API / MCP-tools | машины и агенты |

Правила для всех форматов:
1. Каждый несёт: статус данных пака + версию пака + дисклеймер + дату расчёта.
2. Человекочитаемое и машиночитаемое — всегда парой (MD+JSON, XLSX+JSON).
3. **Печатные формы получают QR-код на живую share-версию** — бумага «протухает»,
   QR отвечает на вопрос «актуален ли этот лист» (реализуемо после Ф4; QR — SVG,
   без внешних сервисов, библиотека `segno` или собственный генератор).
4. Двуязычие RU/KK для шапок печатных форм (в РК документация часто требуется на
   двух языках): поле `project.language` + словарь строк. Дешёво сейчас, дорого потом.

## 7. Технические решения фронта

- **Plotly (3,5 МБ с CDN):** V1/V6/V7/V8 делать собственным SVG (легче, печатается,
  стилизуется). Plotly оставить только для TCC/свипа/ΔU; грузить lazy на экране
  редактора. Скопировать plotly.min.js в `web/vendor/` (self-host: офлайн на
  объектах, корпоративные сети с блокировкой CDN).
- Шрифты Google Fonts → self-host по той же причине.
- PWA/офлайн — не сейчас (v4, при спросе).
- Печать: light-тема через `@media print` (уже в Ф2 плана).
