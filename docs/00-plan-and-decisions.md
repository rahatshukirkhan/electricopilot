# 00 — План, цель, границы и журнал технических решений

Статус: **Этап 1 (спецификация)**. Реализация не начинается, пока спека не написана
и не прошла самопроверку (см. `08-self-check.md`).

## 0.1 Цель

Рабочий прототип AI-ассистента для проектировщика электрики — «копилот». Первый и
единственный в v1 сценарий: **подбор сечения кабеля и аппарата защиты по IEC 60364**
с результатом, который:

- **корректен** (детерминированный расчётный движок, покрытый тестами);
- **обоснован** (каждый шаг с формулой и входами);
- **прослеживаем до норм по механизму** (каждый шаг несёт реальную ссылку на пункт/таблицу
  стандарта; числовые значения — синтетические до загрузки лицензионных данных, `04 §4.2`);
- **аудируем** (полный след рассуждения в структурированном виде + человекочитаемый отчёт);
- **рекомендательный** (обязательная подпись инженера; система не сертифицирует).

По духу — «Claude Science для электрики»: LLM ведёт диалог, объясняет и **независимо
перепроверяет**, но **не является источником чисел**. Числа рождает код.

## 0.2 Границы v1 (scope)

**В объёме:**
- Один радиальный фидер / конечная цепь: НН, переменный ток, 1-фазный (230 В) или
  3-фазный (400 В), медь или алюминий, изоляция PVC или XLPE.
- Расчётная цепочка: расчётный ток `IB` → выбор `In` аппарата → пропускная способность
  кабеля `IZ` с поправками → проверки координации (перегрузка) → падение напряжения →
  термическая стойкость к КЗ (адиабатический критерий).
- Синтетический (нелицензионный) пакет норм-данных со структурой, идентичной таблицам
  IEC, но со **синтетическими** значениями, не выведенными из IEC (см. `04`).
- Интерфейсы: CLI (основной), библиотека (API Python), опционально HTTP (FastAPI).
- LLM-слой на Gemini через OpenRouter: разбор запроса, объяснение, независимая проверка.
- Опциональное сохранение сессий аудита в Neon/Postgres.

**Вне объёма v1 (зафиксировано как ограничения, см. `07`):**
- Защита от поражения (ADS / петля «фаза-нуль» / Zs) — только адиабатика по КЗ, без
  расчёта времени автоматического отключения по Zs.
- Пусковые токи двигателей, гармоники/нелинейная нагрузка на нейтрали, каскад/селективность.
- Прокладка в земле с тепловым сопротивлением грунта как отдельный расчёт (метод D
  поддержан на уровне таблиц-заглушек, без полной модели грунта).
- Многожильные пучки с разной загрузкой, параллельные кабели.
- Проверка соответствия реальным нормативным значениям таблиц (нужны лицензионные данные).

## 0.3 Пользовательские сценарии

1. **CLI, естественный ввод.** Инженер описывает нагрузку словами → Flash-модель
   извлекает структурированный `SizingRequest` → инженер подтверждает → движок считает →
   Pro-модель независимо перепроверяет → выдаётся отчёт с трассировкой и блоком подписи.
2. **CLI, строгий ввод (JSON/флаги).** Без LLM на входе: детерминированный расчёт →
   объяснение (шаблон или LLM) → отчёт. Работает без ключей.
3. **Библиотека.** `size(request) -> SizingResult` для встраивания.
4. **HTTP (опц.).** `POST /size` → `SizingResult` (JSON).

## 0.4 Ключевые технические решения (журнал)

| # | Решение | Обоснование |
|---|---------|-------------|
| D1 | **Детерминированное ядро владеет всеми числами; LLM — только разбор/объяснение/проверка.** | Регулируемый домен: корректность и воспроизводимость важнее гибкости. LLM не галлюцинирует значения. |
| D2 | **Язык — Python 3.11+, менеджер `uv`.** | Численный код + `pydantic` типобезопасность + `pytest`; `uv` уже в системе, ставит нужный Python. |
| D3 | **Схемы — pydantic v2, заморожены в `03` до реализации.** | Контракт-first делает параллельную реализацию безопасной. |
| D4 | **Доступ к Gemini — через OpenRouter (OpenAI-совместимый REST на `httpx`).** | Ключ и кредиты предоставляет пользователь; шлюз к `google/gemini-3.1-pro-preview` (сильная, reasoning) и `google/gemini-3-flash-preview` (быстрая); slug'и конфигурируемы, подтверждены `list_models.py`. |
| D5 | **Норм-данные — СИНТЕТИЧЕСКИЙ пакет (`meta.status=illustrative`), значения не из IEC, подключаемый.** | Копирайт IEC: не скрапить и не воспроизводить лицензионные таблицы. Реальные значения таблиц — само охраняемое выражение, поэтому значения переопределены синтетически; методология и ссылки реальны (`04 §4.1`). |
| D6 | **Подпись инженера — структурное поле `SignOff` со статусом по умолчанию `UNSIGNED_ADVISORY`.** | Невозможно выпустить результат без пометки «рекомендация, не сертификация». |
| D7 | **Гардрейл числовой провенанс: любое число в тексте LLM обязано присутствовать в трассе.** | Защита от галлюцинаций в объяснении; жёсткий режим (`ELECTRICOPILOT_STRICT_PROVENANCE`) переводит отчёт в `NEEDS_REVIEW` при нарушении. |
| D8 | **E2E и тесты не зависят от ключей и БД.** | Прототип запускается «из коробки» в фолбэк-режиме; ключи/Neon расширяют, но не блокируют. |
| D9 | **Персистентность — опциональна; без `DATABASE_URL` пишем JSONL в `./runs/`.** | Аудит-след сохраняется всегда; Neon — апгрейд. |
| D10 | **Клиент LLM при неизвестном slug'е падает с явной ошибкой, а не молча в фолбэк.** | Молчаливый фолбэк маскировал бы misconfig под «LLM выключен». |

## 0.5 Окружение (реализовано в Этапе 1)

- `uv` + Python 3.13 в `.venv`; зависимости в `pyproject.toml`.
- Секреты только через env/`.env` (git-ignored). `.env.example` — без секретов.
- `scripts/list_models.py` — подтвердить точные slug'и Gemini в OpenRouter после ключа.

**Полный набор переменных (`.env.example`, значения-плейсхолдеры):**

| Переменная | Назначение | Дефолт |
|---|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter; пусто → фолбэк-режим | — |
| `OPENROUTER_BASE_URL` | endpoint шлюза | `https://openrouter.ai/api/v1` |
| `ELECTRICOPILOT_MODEL_STRONG` | сильная модель (рассуждение/проверка) | `google/gemini-3.1-pro-preview` |
| `ELECTRICOPILOT_MODEL_FAST` | быстрая модель (интейк/нарратив) | `google/gemini-3-flash-preview` |
| `OPENROUTER_APP_TITLE` / `OPENROUTER_HTTP_REFERER` | атрибуция OpenRouter | `ElectriCopilot` / repo URL |
| `DATABASE_URL` | строка Neon; пусто → JSONL `./runs/` | — |
| `ELECTRICOPILOT_STRICT_PROVENANCE` | строгий числовой провенанс | `true` |
| `ELECTRICOPILOT_LLM_TIMEOUT` | таймаут запроса LLM, с | `60` |

**Требуется от пользователя:** `OPENROUTER_API_KEY` (живые LLM-роли) и `DATABASE_URL` (Neon).
Оба опциональны для запуска — без них прототип отрабатывает сквозной сценарий (D8/D9).

## 0.6 Допущения (кратко; полный список в `07`)

- Значения таблиц норм-пакета — **синтетические**, не нормативные и не из IEC (D5).
- Падение напряжения — установившийся режим, без пусковых просадок.
- `voltage_v`: 230 В для 1ф (L-N), 400 В для 3ф (L-L, линейное).
- Опорные условия поправок: воздух 30 °C, земля 20 °C.
- Стандартные ряды `In` и сечений — **реальные** отраслевые (уникопирайтные факты); синтетика
  касается только значений таблиц (It / k / ka / kg).
